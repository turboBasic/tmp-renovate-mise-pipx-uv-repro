# Renovate bumps a `pipx:` tool and publishes a lock entry mise cannot install

Minimal reproduction for [renovatebot/renovate discussion 47279](https://github.com/renovatebot/renovate/discussions/47279).

## Setup

- Mend-hosted Renovate 44.220.0 on GitHub.com.
- `mise.toml` pins `uv` and one uv-backed tool, `pipx:yamllint` at 1.37.1. `lockfile = true`.
- `mise.lock` and `.mise/locks/pipx-yamllint/1.37.1~52732482/` were generated by `mise lock` on a machine that has `uv`.
- `renovate.json` enables only the `mise` manager, so nothing else edits the sidecar. `uv` bumps are disabled, so the one PR Renovate opens is the yamllint bump to 1.38.0.
- `.github/workflows/ci.yml` runs `mise install --locked`. It passes on `main`.

## Current behaviour

Renovate's PR for `pipx:yamllint` 1.38.0 changes `mise.toml` and `mise.lock` and deletes the 1.37.1 sidecar. The new `mise.lock` entry has no `uv = { path, digest }` line and no new sidecar exists. `mise install --locked` fails:

```text
pipx:yamllint has no uv dependency graph; run `mise lock`
```

## Expected behaviour

The PR commits the new sidecar and its digest, or the artifact update fails. A PR whose lock `mise install --locked` cannot install should not be opened as if it were a normal update.

## Cause

Renovate's sandbox has no `uv`, so `mise lock` there prints `dependency graph skipped: uv >= 0.12.10 is unavailable`, keeps a version-only entry and prunes the old sidecar. `getMiseLockToolConstraints` in `lib/modules/manager/mise/artifacts.ts` provisions `mise`, `node`, `npm`, `golang` and `ruby`, and no tool for the pypi/pipx backend.

## Reproduce without Renovate

```sh
sed -i.bak 's/1\.37\.1/1.38.0/' mise.toml
env -i HOME="$HOME" PATH="$(dirname "$(command -v mise)"):/usr/bin:/bin" \
  MISE_DATA_DIR="$(mktemp -d)" MISE_GLOBAL_CONFIG_FILE=/nonexistent mise lock
mise install --locked
```

The first command prints the `dependency graph skipped` warning, leaves no `.mise/locks/pipx-yamllint/`, and writes a version-only entry. The second fails as above.
